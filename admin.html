Hosting Architecture & Production Deployment

Why GitHub Pages cannot run a backend & how to host this full-stack application

Why GitHub Pages Cannot Run This Application's Backend

GitHub Pages is an exclusively static web host. It serves pre-compiled HTML, CSS, client JavaScript, and images. It does not run Node.js processes, execute server.js, or support server-side SQLite databases. Any changes made in this Admin CMS or Inventory would be lost or impossible without an active Node.js server to handle API routes and persist data to data/prakriti.db.

Recommended Production Hosting Options

Option 1 (Easiest)

Render.com Web Service

1-Click zero-config deployment. Connect your GitHub repository, choose Node runtime, set Start Command to node server.js, and attach a persistent disk for data/.

Build: npm install
Start: node server.js
Option 2 (Modern Cloud)

Railway.app / Fly.io

Instant containerized deployment from Git. Automatically detects Node 24 and provisions high-speed storage for SQLite WAL mode.

PORT: 3000
Persistent Volume: /data
Option 3 (High Performance)

Ubuntu VPS (DigitalOcean / Hetzner)

Run via PM2 process manager behind an NGINX reverse proxy with free Let's Encrypt SSL. Unlimited requests, zero cost limits.

pm2 start server.js --name "prakriti"
pm2 save
